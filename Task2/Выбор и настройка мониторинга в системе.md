# Мониторинг

**В данном случае речь идет о мониторинге производительности.**

## Мотивация

Добавление мониторинга позволит достичь следующих целей:

- Более оперативное реагирование на инциденты.
- Возможность выявления узких мест с целью их устранения для повышения быстродействия системы и улучшения распределения ресурсов.
- Обнаружение существующих проблем до того, как их обнаружат пользователи или будет нанесен существенный ущерб бизнесу. Получение запаса времени для внесения исправлений.
- Возможность раннего анализа и планирования  оптимизации производительности для предотвращения потенциальных проблем под разными нагрузками.
- Ускорение рабочего процесса и DevOps, сокращение в нем количества ошибок, улучшение взаимодействия между командами.
- Повышение удовлетворённости пользователей.

 ## Выбор подхода к мониторингу
 
Будем использовать RED (Request rate, Errors, Duration) подход для системы MES. Это основной фокус, так как соответствует текущим жалобам по задержкам на MES UI (duration) и потерям заказов (errors).

В целом метрики RED
- измеряют показатели, которые важны для конечных пользователей.
- эффективны для сервисов, которые управляются запросами.

Оба критерия соответствуют нашему случаю.

### Предлагаемые метрики

1. Метрики очереди
- Number of dead-letter-exchange letters in RabbitMQ

Покажет кол-во ошибок при взаимодействии CRM и MES через RabbitMQ

- Number of message in flight in RabbitMQ

Покажет насыщенность (заполнение) очереди. Высокие значения будут свидетельствовать о "пред-предельных нагрузках", и что скоро могут наступить потери и отказ в обслуживании.

Метрики производительности, нагрузки и ошибок

2. Метрики для отслеживания нагрузки на APIs:

- Number of requests (RPS) for CRM API
- Number of requests (RPS) for MES API

3. Метрики отклика сервисов
 - Response time (latency) for shop API
 - Response time (latency) for CRM API
 - Response time (latency) for MES API

4. Метрики внутренних ошибок
 - Number of HTTP 500 for shop API
 - Number of HTTP 500 for CRM API
 - Number of HTTP 500 for MES API

5. Метрики системного уровня

 - CPU % for shop API
 - CPU % for CRM API
 - CPU % for MES API

## План действий
1.  Для реализации RED-метода может использоваться Prometheus. Этот инструмент позволяет собирать, хранить и анализировать метрики, визуализировать и создавать предупреждения.
2. MES сервисы должны будут реализовать свои экспортеры в Prometheus или быть подключены к Yandex Метрике.

3. Yandex Метрика должна быть сынтегрирована с Prometheus.
