## Анализ

Заказ может сломаться или зависнуть где-угодно, но стоит обратить внимание в первую очередь на следующие переходы:

1. SUBMITTED -> PRICE_CALCULATED

Заказ должен попасть на вычисление цены из сервиса CRM в MES. Попадает? Вычисляется?

2. PRICE_CALCULATED -> MANUFACTURING_APPROVED
 
Судя по описанию задачи, здесь проблем особых нет, но тем не менее с ростом нагрузки этот переход может сломаться тоже (взаимодействие между сервисами)

3. MANUFACTURING_APPROVED -> MANUFACTURING_STARTED
Заказ подтвержден. Пользователь начинает отсчет времени ожидания. Важно убедиться, что заказ действительно переходит в MES для исполнения.
Если MES перегружен, то вероятность проблем тут очень велика. Их нужно подтвердить, чтобы принять решения, как исправлять.

Хорошо бы настроить трейсинг между CRM и MES.


## Мотивация

Многие ошибки сложно исследовать без достаточного логирования или трейсинга.
Логирование может быть дорого и потребует дополнительного хранилища логов. 

Трейсинг запросов дешевле. Мы получим список вызовов, представленных в виде дерева. По ним можно понять, где и чем оборвалась цепочка вызовов - это обычно быстрее, чем выискивание этой информации в логах. Также у трейсинга как средства устранения неполадок есть дополнительные преимущества, поскольку любое исключение или ошибка обычно фиксируется вместе со всем контекстом запроса.


Внедрение трейсинга может улучшить такие показатели как

    - Сокращение времени на отладку и тестирование. Разработчики смогут больше внимания уделять новым возможностям. 
    - Сокращение количества ошибок: легче найти и исправить ошибки, когда видно, где они возникают.
    - Удовлетворённость клиентов: более оперативная реакция на инциденты. Меньшее кол-во неотвеченных инцидентов и скрытых ошибок.
    

## Предлагаемое решение

- Добавить телеметрию в сервисы CRM_API и MES API при помощи OpenTelemetry SDK (OTel).
- Развернуть Jaeger для визуализации данных телеметрии.
- RabittMQ также поддерживает интеграцию с Jaeger.

## Безопасность

Данные о заказах не должны быть доступны в логах или jaeger UI никому, кроме выделенной группы. Секретные данные не должны передаваться в сообщениях вообще.

Рассмотреть следующие меры:
1. Все коммуникации с jaeger только через TLS.
2. Jaeger может редактировать чувствительные данные по образцам (pattern/replacement).
3. Шифровать хранилище данных.
4. Установить RBAC доступ только из внутренней сети к Jaeger UI
